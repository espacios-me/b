# BotSpace Dashboard

Real-time WhatsApp conversation analytics dashboard with optional Gemini-generated insights.

## Quick start

```bash
pnpm install
pnpm dev
```

```bash
pnpm check
pnpm build
pnpm start
```

---

## 1) Project overview

BotSpace Dashboard is a React + TypeScript application that visualizes conversation activity from the BotSpace public API and renders AI summaries for operational insights. The canonical deployment URL is:

- **https://espacios.me/botspace**

> Route compatibility note: the Cloudflare Worker still redirects legacy `/bot` and `/bot/` to `/botspace`, but `/botspace` is the canonical entrypoint.

## 2) Architecture

### Frontend (client app)

- Stack: React 19, TypeScript, Vite, Tailwind CSS, Recharts.
- Entry: `client/src/main.tsx` → `client/src/App.tsx`.
- Routing: `/` (dashboard) and `/404` inside SPA routing.
- Main page: `client/src/pages/Dashboard.tsx`.
- Core UI modules: `client/src/components/*` and `client/src/components/ui/*`.

### Integration layer

- BotSpace API integration: `client/src/lib/botspace-api.ts`.
- Gemini integration: `client/src/lib/gemini-ai.ts`.
- Data orchestration hook: `client/src/hooks/useBotSpaceData.ts`.

### Backend (Node/Express host)

- Server entry: `server/index.ts`.
- Purpose: serves the production build generated by Vite/esbuild.

### Worker edge layer (Cloudflare)

- File: `worker.js`.
- Responsibilities:
  - Redirect `/bot` and `/bot/` → `/botspace`.
  - Serve `/botspace` and `/botspace/` as `index.html`.
  - Proxy static assets/paths under `/botspace/*` by stripping `/botspace`.
  - Return `404` outside expected scope.

## 3) Data flow and API endpoint docs

### Runtime data flow

1. User opens `https://espacios.me/botspace`.
2. `worker.js` maps the request to `index.html` (or static asset when applicable).
3. Dashboard mounts and `useBotSpaceData()` triggers.
4. Hook requests:
   - `getConversations()`
   - `getDashboardStats()`
5. Dashboard renders cards/charts/table from computed stats + conversation list.
6. AI summary components can call Gemini helpers for insight text.
7. Hook auto-refreshes every 30 seconds.

### BotSpace API endpoints used

Base:

- `https://public-api.bot.space`

Endpoints:

- `GET /v1/{channelId}/conversation?apiKey=...`
  - Fetches channel conversations.
- `GET /v1/{channelId}/conversation/{conversationId}?apiKey=...`
  - Fetches one conversation by ID.

Current channel path in code:

- `/v1/690c66ec2a221421bdc2b6d1/...`

### Gemini endpoint used

- `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent`

## 4) Component structure and state management

### Component structure

- `client/src/pages/Dashboard.tsx`
  - Top-level analytics page.
- `client/src/components/AIInsights.tsx`
  - AI-generated operational summary.
- `client/src/components/ErrorBoundary.tsx`
  - UI-level error containment.
- `client/src/components/ui/*`
  - Shared shadcn-style primitives.

### State management notes

`useBotSpaceData()` maintains:

- `conversations: Conversation[]`
- `stats: DashboardStats | null`
- `loading: boolean`
- `error: string | null`

Behavior:

- Uses async `fetchData()` to gather conversations + derived stats.
- Exposes `refetch()` for manual refresh.
- Runs interval refresh every **30s** via `setInterval`.

## 5) Deployment, configuration, and troubleshooting

### Deployment/configuration

- Build command: `pnpm build`
- Production serve command: `pnpm start`
- Worker route base (canonical): `/botspace`
- Static file behavior in `worker.js` assumes assets are requested as `/botspace/assets/*` (then rewritten to `/assets/*`).

Recommended production configuration:

- Store API keys in environment variables (not hardcoded client bundles).
- Move sensitive API calls behind a server/edge proxy when possible.

### Troubleshooting

- **App loads but route 404s on domain root**
  - Expected: worker only serves under `/botspace`.
  - Open `https://espacios.me/botspace` directly.
- **Assets fail under custom route**
  - Ensure paths remain prefixed with `/botspace` at request time so worker rewriting works.
- **No data on dashboard**
  - Validate BotSpace API key/channel ID and CORS/network access.
- **AI insights missing**
  - Verify Gemini key/configuration and quota.

## 6) Security and performance

### Security

- Do not expose production secrets in frontend source.
- Prefer server-side secret handling and short-lived tokens.
- Add rate limiting and origin controls on proxy endpoints if introduced.

### Performance

- Keep dashboard payload lean (paginate/filter conversations if volume grows).
- Cache static assets at edge (`Cache-Control` already set for HTML route in worker).
- Consider debouncing manual refresh actions and reducing redundant API calls.

## 7) Detailed reference

### Routes (must match `worker.js`)

- Canonical dashboard:
  - `GET /botspace`
  - `GET /botspace/`
- Legacy redirect:
  - `GET /bot` → `301 /botspace`
  - `GET /bot/` → `301 /botspace`
- Static paths forwarded by worker:
  - `GET /botspace/assets/*` → forwarded as `/assets/*`
  - `GET /botspace/*` → forwarded as `/*`
- Outside scope:
  - Other paths return `404`.
